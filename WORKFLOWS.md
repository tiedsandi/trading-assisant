# AI Development Workflow

This document defines the collaboration workflow between the project owner,
ChatGPT as planner/reviewer, and local coding agents.

## Roles

### Project Owner
- Defines product intent and makes final decisions.
- Provides implementation instructions to coding agents.
- Commits and pushes approved changes.

### ChatGPT
Acts as planner and reviewer.

Responsibilities:
- Clarify feature requirements before implementation.
- Define goal, user flow, data, scope, and acceptance criteria.
- Produce `instruksi.md` content for coding agents.
- Review coding-agent handoff reports.
- Request targeted diffs/files when deeper review is necessary.
- Decide whether work is ready to commit or requires revision.

### Coding Agent
Codex, Claude Code, Gemini, or another repository-aware coding agent.

Responsibilities:
- Follow AGENTS.md.
- Understand the task before editing.
- Inspect relevant existing code.
- Plan before implementation.
- Implement only requested scope.
- Verify changes.
- Update project context.
- Produce a Handoff Report.

---

## Development Flow

Design
→ Instruction
→ Understand
→ Inspect
→ Plan
→ Implement
→ Verify
→ Document
→ Handoff
→ Review
→ Commit
→ Next Task

Do not start implementation while material product requirements are ambiguous.

---

## Feature Design

Before implementation, define:

- Goal
- User flow
- Functional requirements
- Data to store
- API behavior when applicable
- UI behavior when applicable
- Out of scope
- Acceptance criteria

If these are materially unclear, clarify them before generating the final
implementation instruction.

---

## Implementation Instruction (`instruksi.md`)

`instruksi.md` refers to a temporary implementation prompt generated by
ChatGPT and copied to a coding agent.

It is NOT a repository file.

Each instruction should contain:

1. Execution Protocol
2. Task
3. Goal
4. User Flow
5. Functional Requirements
6. Data requirements
7. API requirements when applicable
8. UI requirements when applicable
9. Constraints
10. Out of Scope
11. Acceptance Criteria
12. Required Handoff Report

The coding agent must understand and inspect before implementing.

If repository reality conflicts with the instruction, stop and report it.

If a material ambiguity could change the implementation, ask for
clarification.

Otherwise proceed without waiting for unnecessary approval.

---

## Handoff Report

Every implementation task must end with:

### Status
DONE / PARTIAL / BLOCKED

### What Was Implemented

### Files Changed

### Database Changes

### API Changes

### Verification
PASS / FAIL / NOT RUN for relevant checks.

### Acceptance Criteria
Use checked/unchecked items.

### Decisions / Assumptions

### Issues / Remaining Work

### Git
Commit and push status.

### Suggested Review
List critical files or areas worth manually reviewing.

---

## Review Policy

ChatGPT reviews the Handoff Report against the original instruction and
acceptance criteria.

Possible outcomes:

### APPROVED
Implementation appears complete.
Project owner may commit and push.

### REVIEW REQUIRED
Request only relevant diffs/files for deeper inspection.

### REVISION REQUIRED
Generate a focused revision instruction for the coding agent.

Do not request the entire codebase by default.

---

## Git Policy

Coding agents do not commit or push unless explicitly requested.

Default flow:

Implementation
→ Handoff
→ Review
→ Approval
→ Project owner commits
→ Push
